# ШТАБ ЛС

Локальное однопользовательское приложение для учёта полётных смен, рабочего времени и отдыха. Код размещается на GitHub Pages, рабочие данные сохраняются только в IndexedDB текущего браузера.

## Что уже работает

- карточки сотрудников со связанными наборами «эксплуатант — тип ВС — занимаемые кресла — допуск к ночным полётам»;
- эксплуатанты КВП/АОН/АР и типы ВС A109, AW109, AW139, AS350, EC130, R44, R66, BO105 и Bell407 выбираются чекбоксами;
- ночной допуск задаётся отдельно для каждого выбранного типа ВС;
- редактирование и удаление сотрудников;
- учёт только свершившихся смен и других видов занятости без дополнительного статуса;
- восемь видов занятости: полётная смена, командировка, работа в офисе, периодическая и наземная подготовка, ожидание полёта, отпуск и выходной;
- для «Ожидания полёта» время начала и рабочее время не вводятся;
- для записи «Выходной» основным значением показываются 24 часа; полный непрерывный отдых от окончания предыдущей работы до начала следующей выводится отдельной поясняющей строкой с границами расчёта;
- несколько смен одной даты объединяются одной ячейкой даты в журнале;
- в месячном плане сотрудника с нужным допуском можно назначить на несколько разных бортов; календарь предупреждает о других назначениях, а план выгружается в оформленный Excel;
- командировка, отпуск и периодическая подготовка на произвольный период с отдельной записью каждого календарного дня;
- воскресенья внутри периода периодической подготовки автоматически отмечаются как выходные и остаются связанными с редактируемым периодом;
- для периодической подготовки время начала и рабочее время не вводятся; отдых на границе с полётной сменой принимается соответствующим установленным нормам и не формирует предупреждение;
- несколько полётов внутри одной смены;
- при отметке «Разделённая смена» форма раскрывает два полных набора данных — для первой и второй части; обе части связаны и считаются одной разделённой сменой в контроле отдыха;
- каждый полёт отображается отдельной строкой в едином журнале;
- выбор кресла «КВС» или «Пилот-инструктор» для каждого полёта;
- при выборе кресла «Пилот-инструктор» можно указать КВС из числа допущенных сотрудников; общая смена отображается у обоих членов экипажа, но считается одной сменой;
- тип ВС выбирается из допусков сотрудника, после чего бортовой номер выбирается из зависимого списка для A109, AW109, BO105, R44, R66, AS350 и Bell407;
- для Bell407 доступен борт RA-01619;
- при создании новой смены сотрудник обязательно выбирается вручную и не подставляется автоматически;
- цели полёта: КВП, АОН, АР и АОН (УТП);
- ввод времени цифрами без обязательного двоеточия;
- рабочее, полётное и ночное время;
- для каждого полёта можно необязательно указать время «В рабочее время не учитывается»; оно вычитается из общего рабочего времени, не изменяя границы смены и отдыха;
- расчёт окончания смены и отдыха от самой поздно завершившейся смены рабочего дня;
- редактирование и удаление смен;
- фильтры журнала по периоду и сотруднику, кнопки «Сегодня» и «Текущий месяц»;
- отдельная колонка примечаний в едином журнале;
- активные часы UTC и местного времени Сочи, Перми и Магадана;
- показатель количества выполненных полётных смен текущего месяца на главной;
- PDF-отчёт о налёте за произвольный период с таблицей «Кресло — Тип ВС — Цель — Налёт — Из них ночь»;
- PDF «Отчёт о занятости»: отдельно по выбранному сотруднику либо по всему составу, включая дни без записей, отдельную строку для каждой смены, тип и бортовой номер ВС, признак разделённой смены, рабочее, полётное, инструкторское и ночное время;
- итоговая строка по каждому сотруднику в отчёте о занятости;
- PDF «Отчёт по нарастающему налёту» по выбранному сотруднику: исходный итог берётся из всех полётов до начала периода, после чего каждая новая запись увеличивает нарастающий итог;
- PDF «Итоговая справка о налёте» за период: пилот, тип ВС, налёт, ночь и инструкторский налёт без разделения по эксплуатантам;
- фирменный логотип Центра авиации «Солярис» в PDF-отчётах;
- контроль ежедневного отдыха не менее 12 часов;
- контроль еженедельного отдыха не менее 42 часов после шести рабочих дней;
- отображаемое непрерывное время отдыха от 42:00 выделяется зелёным жирным текстом, менее 42:00 — красным жирным;
- контроль отдыха не менее 48 часов после двух разделённых полётных смен подряд;
- пересечения смен не выводятся как нарушения в блоке контроля;
- раздел «Личные дела» для каждого пилота;
- личное дело собрано в понятную карту разделов: карточка, образование, свидетельства, медицина, документы, полномочия, виды полётов, минимумы, подготовка, периодика, файлы и история изменений;
- личный состав в разделе «Личные дела» отсортирован по алфавиту и фильтруется по эксплуатанту, типу ВС и креслу;
- налёт выбранного сотрудника за текущий месяц в шапке личного дела;
- лётная книжка внутри карточки каждого сотрудника с общим налётом и разбивкой по типам ВС, КВС, 2П, инструкторскому, ночному и ППП;
- исходный накопленный налёт вводится контрольной точкой на выбранную дату, после чего сайт автоматически прибавляет все более поздние полёты из единого журнала;
- можно хранить несколько контрольных точек; для расчёта используется самая поздняя по дате;
- раздел «Контрольный журнал» с отдельными вкладками «Тип», «Ночь» и «Контроль»; «Тип» и «Ночь» показывают все начавшиеся сроки, а «Контроль» — предупреждения с главной;
- контроль 90 календарных дней от последнего полёта на каждом допущенном типе ВС и от третьей наиболее поздней ночной посадки;
- отсутствие полёта на типе или трёх ночных посадок не считается ошибкой: строка появится в контроле только после возникновения опорной даты;
- выгрузка контрольного журнала в оформленный Excel за выбранный период;
- на главной отображаются пять ближайших или уже просроченных пунктов контроля в порядке срочности;
- отдельный раздел «Месячный план» после личных дел: матрица по всем бортам, датам месяца и ролям «Основной/Резерв»;
- отдельный раздел «Фактический план»: наглядная месячная матрица занятости по каждому сотруднику с быстрым переходом к редактированию фактической записи;
- единое окно «Запись занятости»: сотрудник, один день/произвольный набор дат/период, вид занятости и, для полёта, один или несколько доступных бортов;
- назначение в месячном плане только свободных сотрудников с допуском на соответствующий тип ВС;
- выходной, отпуск, подготовка и другая занятость блокируют назначение полёта с понятным объяснением причины; существующий полёт аналогично защищён от несовместимой записи;
- единый журнал показывает только фактически внесённые смены; месячный план используется в отчёте о занятости как подстановка для дней без фактической записи;
- если активный сотрудник не назначен на борт и другая занятость не указана, месячный план автоматически ставит «Ожидание полёта»; после 6 рабочих дней подряд, включая фактические и вручную запланированные дни, следующий свободный день становится «Выходным»;
- нижние строки месячного плана редактируются непосредственно из таблицы через кнопку «+» в нужной ячейке;
- отображение в месячном плане занятости, уже внесённой в журнал смен;
- импорт книги рабочего времени в «Полётные смены» с выбором начальной даты, предварительной проверкой сотрудников и допусков, разворачиванием объединённых ячеек и защитой от дублей;
- импорт Excel-выгрузки «Сертификации» из Авиабит;
- предупреждения о сроках до 14 дней, за 15–45 дней, просрочке и отсутствующих данных;
- ручное добавление и изменение записей личного дела;
- рабочий раздел «Документация» с перенесённым реестром ЛС: приказы, акты, протоколы и справки;
- добавление, изменение и удаление записей реестра с предложением следующего номера по разделу и году;
- отдельные анкетные данные сотрудников для автозаполнения типовых форм;
- формирование Word-приложения к пилотскому свидетельству из анкетных данных и записей личного дела;
- формирование заявки в АУЦ в Word с выбором нескольких сотрудников и ручной проверкой каждого поля перед выгрузкой;
- формирование вкладыша квалификационной проверки в оформленном Excel;
- внутренний справочник АУЦ, программ обучения, телефона и электронной почты отправителя;
- исходные образцы документов сохранены в проекте и доступны из раздела «Документация»;
- локальное автосохранение;
- резервная копия и восстановление в JSON.

## Публикация на GitHub Pages

1. Создайте новый репозиторий на GitHub, например `shtab-ls`.
2. Загрузите в него содержимое проекта и отправьте изменения в ветку `main`.
3. Откройте `Settings → Pages`.
4. В разделе `Build and deployment` выберите `GitHub Actions`.
5. Дождитесь выполнения процесса `Deploy to GitHub Pages` во вкладке `Actions`.

Файл `.github/workflows/pages.yml` уже содержит необходимую настройку публикации. При каждом обновлении ветки `main` сайт пересобирается автоматически.

## Работа с данными

После первого открытия:

1. Откройте `Личные дела` и нажмите `Загрузить Excel`.
2. Выберите выгрузку «Сертификации» из Авиабит. Сайт определит Ф. И. О., создаст карточку и покажет предварительный итог.
3. Нажмите `Импортировать`. При повторной загрузке обновятся только записи Авиабит, а ручные записи сохранятся.
4. Добавляйте полётные смены и проверяйте рассчитанное рабочее время, отдых и общий список предупреждений на главной.
5. Чтобы перенести рабочее время из существующей книги, откройте `Полётные смены → Импорт рабочего времени`, укажите начальную дату, выберите файл и проверьте предварительный итог. Записи попадут в журнал только после нажатия `Добавить в журнал`.
6. Регулярно используйте команду `Скачать резервную копию`.

Excel обрабатывается прямо в браузере и никуда не отправляется. Для расчёта срока используется колонка `Конец`; пустая дата не рассчитывается автоматически и помечается как `Без срока` либо `Нет данных`.

Данные не входят в репозиторий и не отправляются на GitHub. Они привязаны к браузеру и устройству. Очистка данных сайта удалит локальную базу, поэтому резервное копирование обязательно.

## Локальный запуск для разработки

```bash
npm ci
npm run dev
```

Статическая сборка для GitHub Pages:

```bash
npm run build:github
```

Результат появится в каталоге `out`.

## Статус

Это первая рабочая версия. В контроль заложены согласованные базовые пороги приказа Минтранса России от 10 ноября 2025 г. № 381: 12, 42 и 48 часов. До переноса реальных производственных данных необходимо добавить шифрование локального хранилища и резервной копии, а также подтвердить применимость исключений и внутренних правил организации.
